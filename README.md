# Nymbo

Адаптивный MVP помощника по питанию, созданный по приложенному HTML-референсу: светлый фон, тёмные панели, оранжевые кнопки, лаймовые акценты, Golos Text и Unbounded. Приложение на HTML/CSS/JavaScript, статический сервер на Node.js. Сборка не нужна.

## Посмотреть без установки

Откройте файл `index.html` в репозитории GitHub, нажмите **Download raw file** (значок скачивания), затем откройте скачанный файл в браузере. Фотографии блюд, стили, шрифты и логика встроены в один HTML; сервер не нужен. GitHub в обычном просмотре файла показывает исходный код, а не работающий сайт.

Для обновления самостоятельного HTML после изменений: `npm run build:preview`. Если включить GitHub Pages через Settings → Pages → Deploy from a branch → main → / (root), этот же файл станет главной страницей сайта. Pages пока не включён автоматически.

## Запуск

Нужен Node.js 20 или новее.

```sh
cd /workspace/nymbo_sites
npm ci
npm start
```

Сервер слушает порт 3000 на всех интерфейсах. Другой порт: `PORT=3001 npm start`. Проверка готовности: `curl -fsS http://127.0.0.1:3000/health`. Для самого сайта npm-зависимости не нужны: `node server.mjs` запускает его непосредственно. Зависимости в package.json используются браузерными тестами.

Можно размещать содержимое `public/` на любом статическом хостинге. Маршруты используют hash-навигацию и не требуют серверного перенаправления.

## Что работает

- Чат с локальным помощником: быстрые действия, обычные сообщения и распознавание периода, числа людей, времени и бюджета. Например: «Меню на неделю для двоих». Существующий чат пользователя не был доступен; его содержимое не воспроизводилось.
- Вкусы: фотографии блюд, три изменяемых оценки, поиск и фильтры по приёму пищи.
- Профиль: бюджет на день для всех, период, порции, время, цель, кухни, тип питания, аллергии и исключения.
- Подбор меню с обязательными ограничениями и проверкой дневного бюджета. Если подходящих вариантов нет, старое меню сохраняется и выводится причина.
- Точечная замена, удаление, перенос между днями, изменение порций, рецепты и ориентировочные стоимость/калорийность. После ручных изменений превышение бюджета отмечается предупреждением.
- Покупки: объединение одинаковых ингредиентов и единиц, флаг «есть дома», ручные количества, дополнительные товары, сброс количества к расчёту меню, экспорт TXT.
- Выбор ВкусВилла или Перекрёстка; подготовка списка, ссылки на поиск товаров, переход в магазин. Неподобранные товары явно обозначены; цена, упаковка и наличие не выдумываются.
- Демо-профили поваров, форма с датой/временем/числом людей/форматом, сохранение заявки со снимком меню и ограничений. Статус не изображает подтверждённое бронирование.
- LocalStorage: профиль, вкусы, меню, покупки, чат и заявки; экспорт JSON и удаление данных с подтверждением.
- Защита отображения пользовательского текста от HTML-инъекций, состояния пустых списков и ошибок, адаптация к мобильному экрану.

## Проверки

```sh
npm run check
npm test
npm run test:e2e
```

9 тестов логики и 3 браузерных сценария. В этой облачной среде используется `/usr/bin/chromium`. В другом окружении задайте `CHROMIUM_PATH` или установите стандартный Chromium Playwright: `npx playwright install chromium`. Сервер для тестов запускается автоматически; уже запущенный Nymbo может переиспользоваться. Браузерные тесты охватывают полный путь, отдельную замену с сохранением остальных строк, покупки, экспорт, заявку, перезагрузку, HTML-инъекции, блокировку заказа при изменении ограничений и мобильные экраны с загрузкой локальных фотографий.

## Честные границы MVP

Чат использует локальные сценарии, а не языковую модель. Данные хранятся только в текущем браузере, без аккаунта и синхронизации. Цены и калорийность являются демонстрационными оценками, а каталог рецептов небольшой. Произвольные исключения сопоставляются с названиями известных ингредиентов и аллергенов; медицинская оценка составов и следов аллергенов не производится. Состав упаковок и перекрёстное загрязнение нужно проверять отдельно.

**Заполненная корзина не подключена.** Без предоставленной официальной документации и партнёрских доступов не подтверждена возможность передачи корзины в выбранные магазины. `prepareOrder` в `public/model.js` явно возвращает `cartSupported: false`, `matched: false`. Ссылки ведут на поиск, не на выбранный SKU. Для реальной интеграции нужен серверный адаптер официального API: поиск SKU, состав и аллергены, упаковки, доступность, актуальная цена, подтверждение замен пользователем и получение официального URL корзины. Ключи держать только на сервере. Не автоматизировать авторизацию в чужом аккаунте и не имитировать успешный заказ.

**Заявки поварам локальные.** Их никто не получает; оплата и подтверждение бронирования не реализованы. В промышленной версии нужны реальные профили с согласием владельцев, сервер заявок и подтверждённые слоты.

## Изображения

Фотографии блюд и поваров локальные WebP, шрифты локальные WOFF2. Источники и ограничения использования перечислены в `ASSETS.md`. Часть фотографий продуктов загружается с Unsplash; при сетевой ошибке выводится «Фото недоступно». В этой облачной среде `images.unsplash.com` запрещён сетевой политикой, поэтому внешние фотографии продуктов сейчас не проверены. Для полностью автономного каталога продуктов нужно добавить фотографии с подтверждёнными правами и положить их в `public/assets/`.

Перед коммерческой публикацией необходимо подтвердить права на каждую фотографию или заменить демонстрационную подборку на собственные/лицензированные изображения. Портреты не представляют настоящих доступных исполнителей.

## Файлы

- `public/app.js` — интерфейс и локальное хранение.
- `public/model.js` — каталог, ограничения, подбор меню, покупки и контракт магазинов.
- `public/style.css` — дизайн и адаптивность.
- `server.mjs` — статический сервер и health endpoint.
- `tests/` — тесты логики и браузерные сценарии.
